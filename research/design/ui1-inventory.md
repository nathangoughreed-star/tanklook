# UI1: inventory of today's UI (lane UI1, 2026-11-13, request R27; Coordinator 24)

Facts only, no design. Source: origin/main at build 1922 (commit f8132097), read from the code and from the real app (aquarium scope, Chrome, 1600x900). Screenshots are in `research/screens/UI1/` (named `NN-surface.png`; the "Shot" column below). The test tank in the shots is the "Planted community" starter (40 breeder, 40 animals, plants, hardscape) with the `midplanted` equipment preset (hang-on filter, heater, liquid CO2). Scripts used (not app code): `scripts/ui1-*.mjs`.

## 0. Summary for Nathan (read this, then stop if you like)

1. **One 2,600-line file runs most of the UI.** `src/ui/panels.ts` is a single function (`attachPanels`, lines 114-2578) holding 529 id lookups, 443 DOM operations, 116 scene-edit calls and the only copy of many rules (tank shape rules, stocking adds, species graying, file open/save). It has no tests; nothing can import from it.
2. **The page is one big hand-written `index.html` (548 lines, 605 ids) that `panels.ts` is wired to by id.** The left menu is 8 sections that open to 1,000-1,800 px each; about 60 more surfaces are created in code on top of it. 11 tests read `index.html` as text and 14 read `panels.ts` as text, so even renaming an id breaks tests.
3. **About a quarter of `src/ui` (3,845 of 14,828 lines) has no live door.** Guided setup (World / Equipment / Limits / Starting Point), Visual Discovery, Explore, the A/B screen (`?ab=1` only), the guide/coach, and the animal-first stocking screen are built, tested and still loaded, but nothing visible opens them (about 3,845 lines in 28 files). The whole "Quick Setup" block (Style, Shuffle, plant care, densities, care gates, Browse looks) sits in a hidden `<div id="quickHome" hidden>`; its code still runs.
4. **The same setting is edited in several places, and some are stored twice.** Budget / upkeep / time / space / experience each have 3-5 editors; room temperature is stored in two fields (`tech.roomC` and the brief) with a precedence rule; "owned gear" has 7 doors. The pieces of the engine are single-source; the UI is not.
5. **The engine is already cleanly split from the UI in most places:** 94 UI files, 53 of them imported by tests, pure `*Logic.ts` / `logic.ts` files carry the decisions (e.g. `setupBrief.ts` 36 tests, `stockPlanLogic.ts` 25 tests). The tangle is concentrated in `panels.ts`, `techMenu.ts`, `fullnessTile.ts`, `demandPanel.ts`, `ownedGear.ts`. `style.css` is 1,637 lines / 944 classes grown one lane at a time (about 33 two-letter lane prefixes).

## 3. How it is wired

**Start-up (`src/main.ts`, 74 lines):** `applyScopeToDom()` (aquarium wording) -> build tag -> service worker (prod) -> `Store.loadLocalChecked()` (corrupt save told apart from none) -> `applySavedFx()` -> `new Store` -> `new Viewer(canvas, #view, store)` -> `attachPointer` (picking only counts when the matching menu is open: `render/menuFocus.pickSec`) -> **`attachPanels`** (everything in section 1b, the file dialogs, the start dialog) -> `attachGroupBar`, `attachBrushBar`, `attachFullnessTile`, `attachSideOverlays`, `attachParGuide`, `attachLightHover`, `attachLightContours`, `attachSetupSheet`, `attachReport`, `attachAR` -> dev handle `window.__gb` (dev server only) -> share hash opens its tank; else `ui.resume()` if a save exists, else `ui.showStart()`. Inside `attachPanels`, 14 modules load lazily after first paint (briefBar, checksStrip, discover/*, equipmentWarn, infeasibleCard, limitsPanel, myEquipment, ownedGear, quickPrefs, report, rulesSwitch, stockPlan, suggest).

**How panels attach and talk:** panels read and write one `Store` (scene JSON, undo stack, listeners). Writes: `store.edit(fn)` / `update` / `editTank(i, fn)`. Reads: `store.subscribe(listener)` (30 call sites in `src/ui`); `panels.ts sync(full)` (line 2037, about 420 lines) pulls every control from the scene after each change. The viewer is a second channel: panels call `viewer.invalidate / rebuild / terrainEdit / setPreview / thumbnail` (about 55 calls in `panels.ts`) and the viewer calls back through `onDrawn` (label and readout refresh). Overlays on the canvas (tile, cost chip, notes, water chip, group / brush bars) are separate DOM nodes laid over `#view` and each subscribes on its own. Cross-module doors are small registries: `discover/entry.ts` (`openDiscovery`, `registerInline`), `onSpaceFork` (`fullnessTile.ts`), `openOwned` callback passed around.

**Split view (SV1):** with two tanks, `sideOverlays.ts` builds a second copy of Habitat check, cost chip, Notes and Water chip per side; each copy runs the same code on `sideStore(store, i)` (`sideStore.ts`, a `Proxy` that pins `tank`, `effTank`, `scene.active`, `edit` and `targets` to tank `i`). The left menu shows only the active tank (`store.tank`); the "Edit" tick on each tab decides which tank(s) the menu edits.

**Scope switch (`src/scope.ts`, 38 lines):** `aquarium` (default) or `all` (`?scope=all`; vitest forces `all`). Read by `scopeDom.ts` once at start-up (static wording), and by the choke points that filter lists (world, species, plants, styles, gear, tanks, Discover's pool). It is a filter, not a UI mode: terrarium code and data are all still there.

**`style.css`:** 1,637 lines, 159 KB, 1,779 rules, 944 distinct classes, 37 id selectors, 43 `@media` blocks, 39 CSS variables but 470 colour literals, 37 font-size values, 29 border-radius values, 17 z-index values, 10 `!important`. Organised by 86 comment blocks, nearly all named for the lane that added them (66 lane tags mentioned; about 33 two-letter class prefixes such as `ft` 106 rules, `vd` 103, `sg` 96, `sp` 91, `ex` 84, `qp` 73, `da` 68, `td` 44). Distinct styles by class-name pattern (rough): **22 card** classes (`spCard`, `libcard`, `bpCard`, `sgCard`, `qp-card`, `start-mode-card`, `gear-card`, `abcard`, `dq10-card`, ...), **29 pill / chip / tag / badge** classes, **24 panel / box / tile / float / pop** classes, **16 dialog / sheet** classes, **10 button-family** classes (`btns`, `linkbtn`, `sidetog`, `dmtog`, `spLink`, `startbtns`, ...). In templates, 63 distinct classes sit on `<button>` elements (top: `primary` 52, `linkbtn` 28, `spLink` 16, `sidetog` 11, `startpath` 7) and 256 buttons carry no class and take the tag style. Class counts are by name pattern, not by looking at each rule.
